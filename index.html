Qué hace la automatización

Ordena los campos, valida información y prepara un resumen, una respuesta sugerida y una próxima acción para revisar.

Qué muestra esta web

Una interfaz local para enseñar el producto: formulario, panel, estados, resumen simulado, respuesta sugerida y seguimiento.

Preparación futura

Payload futuro para n8n, listo para revisar antes de conectar nada.

Esta demo ya muestra qué datos deberían viajar a un backend o webhook seguro cuando el producto deje de ser local. No envía datos todavía, no guarda credenciales y no llama a servicios externos desde el navegador.

Campos que saldrían del MVP

El objetivo es que n8n reciba una solicitud clara, con contacto, necesidad, estado, seguimiento, respuesta sugerida e historial para poder guardarla en Google Sheets, base de datos o futuro CRM.

  • cliente_nombre y datos de contacto.
  • servicio_tipo, presupuesto, urgencia y descripción.
  • respuesta_sugerida, preguntas clave y seguimiento.
  • historial_actividad para trazabilidad comercial.

No envía datos todavía. La conexión real debe pasar por backend seguro.

Preparación backend

Modelo de datos futuro para pasar de demo local a CRM real.

Esta sección ordena las entidades que harían falta en una base de datos cuando el producto evolucione. No crea una base de datos real, no conecta servicios externos y no cambia el funcionamiento local.

01

Negocio

Configuración del cliente: nombre comercial, sector, canales y preferencias de respuesta.

02

Contacto

Persona o empresa que pide presupuesto, con email, teléfono y origen de entrada.

03

Solicitud

Necesidad concreta, servicio, presupuesto, urgencia, estado comercial y adjuntos.

04

Seguimiento

Próxima acción, fecha prevista, cadencia 24/48/72 horas y resultado del contacto.

05

Mensaje

Respuesta sugerida, canal preparado, asunto de email y texto copiado por el negocio.

06

Evento de automatización

Registro de envíos a n8n, errores, reintentos y sincronizaciones futuras.

Decisión pendiente: elegir más adelante entre Supabase, SQLite/PostgreSQL o backend propio. En esta fase solo se documenta el contrato para no bloquear la demo.
